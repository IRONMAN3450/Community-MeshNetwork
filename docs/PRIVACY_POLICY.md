## 1. What this policy covers

This policy describes how the operator handles personal information when you use the Community Mesh website and, once enabled, its account, incident-reporting, SOS, location, and communication features (the **Service**).

Community Mesh is a disaster-preparedness project. The current website includes demo interactions. In the code reviewed for this draft, the login and signup forms do not send credentials to a server or create accounts; SOS and quick-reply actions show simulated messages; the map page can request browser location only if the user chooses its location control. Confirm these facts against the deployed version before publication. If a backend, analytics, or external service receives information, update this policy to describe it accurately.

## 2. Information the live Service may handle

The operator should collect only what is needed for each feature. Depending on the features actually enabled, that may include:

- **Account details:** first and last name, email address, phone number, selected account role, and authentication information. Passwords must be stored as a secure one-way hash, never as plain text.
- **Sign-in details:** account identifier and, if social sign-in is enabled, the provider and provider account identifier and the profile details you authorise the provider to share. Do not collect or store a provider's client secret in the browser.
- **Emergency reports and messages:** emergency category, message text, report time, status, and information needed to coordinate a response.
- **Location:** precise location only when you choose a location-enabled feature and grant the browser permission, or when you include location in a report. Explain the sharing audience at the point of collection.
- **Technical and security records:** information such as request time, IP address, browser/device details, and security logs if the deployed hosting or application actually records them. Confirm this with the hosting provider and configuration.

**Do not publish this list unchanged until every item is confirmed.** Remove any category the Service does not collect and add all actual categories, including cookies, analytics, maps, or hosting logs where applicable.

## 3. Why information is used

For a live Service, the operator may use relevant information to:

- create and manage accounts and authenticate users;
- receive, display, route, and track emergency reports or messages that the user asks to send;
- share an emergency report with the recipients shown to the user, such as designated responders or nearby network participants, where that feature is enabled;
- protect accounts and the Service, investigate abuse, and maintain service reliability;
- respond to support requests and meet applicable legal obligations.

The operator should provide a clear notice and obtain any consent required for each purpose before processing personal information. Do not use emergency information for advertising or unrelated profiling.

## 5. Location and emergency information

Location is sensitive in a disaster-response context. Ask for it only when needed, explain whether it will be shared and with whom, and provide a way to use the Service without location where practical. Browser permission is controlled by your device/browser; turning it off may limit location-based features.

Emergency reports may reveal health, safety, or other sensitive circumstances. Include only what is needed to request help. Do not assume a report is private if the live feature shares it with responders or network participants; the feature must explain its audience before submission.
